Vigil is out: rest shrines, respawning enemies and echoes where you fell, for RPG Maker MZ

Vigil puts the Souls loop into an MZ project as one plugin set. Tag an event <vigil: shrine> and a shrine is drawn on that tile. Resting there heals the party, sets where it wakes, and brings back the enemies you tagged, on every map, some of them stronger each time. When the party falls it wakes at the shrine, and what it carried waits at the place of the fall inside an echo of the party leader that replays the last steps. Walk back and take it.

Two things we found by running it in the engine

The first version drew the shrine's fire inside the map layer. MZ darkens that layer with the screen tint, so at dusk the fire went dark with the rest of the town and lit nothing. The fire, its glow and the light it throws on the ground now sit in their own layer just above the map, outside the tint but still inside the screen's fade and flash. At night the shrine is the light in the scene. By day it is a soft warmth.

The second was a notetag. <vigil-form: cairn> reaches the plugin as " cairn", with the space after the colon, and the first version matched it without trimming. Every chosen form, fuel, relic and weathering was ignored in the real engine while the headless tests, fed "cairn", passed. It is trimmed now, and a test feeds it the shape MZ really sends.

What was tested

Everything ran in MZ's own runtime from the zip on the page: real battles from encounter events, every respawn rule, a wipe in battle and a wipe on the map by poison, the echo replayed and reclaimed on the same map and on another, every parameter in the Readme, all four plugin commands, the save round trip, a save made before Vigil, Vigil uninstalled with a save that used it, and a fresh MZ project with the stock database at the stock screen size.

Vigil on itch.io. The code and graphics were made with generative AI; every shrine, fire, echo and scene is drawn by that code at run time.

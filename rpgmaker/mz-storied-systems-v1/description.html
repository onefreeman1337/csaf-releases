Storied Systems adds 4 signature RPG systems to RPG Maker MZ, built from your own database and art: run maps, enemy intents, party skits and paper cutouts.

Four parts, 11 raw JavaScript plugin files, no image files. Use one part, any two, or all four: each works alone, and all four were tested on together in the engine. Licence: any commercial or free RPG Maker project, no royalty; the source may not be redistributed as a plugin pack.

⚠️ Compatibility: the question you actually have

Tested against RPG Maker MZ with the stock scripts unmodified, verified by running the plugin in the real engine rather than only in tests.

Plugin Manager order:

  1. ForesightCore.js: Storied Systems / Foresight core: reads a chosen skill into a forecast (no drawing, no engine patches).
  2. ForesightDraw.js: Storied Systems / Foresight drawing: the forecast plate, the target card and the clash burst.
  3. Foresight.js: Storied Systems / Foresight: every enemy shows what it will do next, drawn from the skill it chose. Moves can clash.
  4. AsideCore.js: Storied Systems / Aside: the rules (skit tags, availability, expiry, party chat pools, motions). Needs Aside.js.
  5. AsideDraw.js: Storied Systems / Aside: the drawing (painted backdrop, portrait frames, captions, tab, log, ring). Needs Aside.js.
  6. Aside.js: Storied Systems / Aside: optional party skits the player chooses to watch, staged with your own faces on the map painted down, a skit log and party...
  7. PapercutCore.js: Papercut 1/2 - the paper itself: 20 stocks, the die-cut, the card back and the turn. Needs Papercut.js.
  8. Papercut.js: Papercut 2/2 - your own characters as paper cutouts that spin to turn, on the map and in battle.
  9. DelveCore.js: Storied Systems / Delve: the rules (act map generation, fairness rules, runs, reward drafts, saves). Needs Delve.js.
  10. DelveDraw.js: Storied Systems / Delve: the drawing (the chart in ink and wash, node marks, fog, reward cards). Needs Delve.js.
  11. Delve.js: Storied Systems / Delve: Slay the Spire-style run maps. Every run draws a branching chart through your own battles, events, shops and rest sites.

This order reads sensibly in the list and nothing depends on it. Every check of the four parts working together was run three times, with all 11 files in alphabetical order, in reverse order and in a shuffled order, and passed each time. Install only the parts you want: each part's own files. Aside and Delve both extend Scene_Map.updateScene, Window_MenuCommand.addOriginalCommands and Scene_Menu.createCommandWindow, and each calls the original it saved, so both parts' additions run in either order.

Core methods extended: 27 by saved-original prototype extension, none replaced: Game_System.prototype.onAfterLoad, Scene_Map.prototype.createDisplayObjects, Scene_Map.prototype.start, Scene_Map.prototype.updateScene, Window_MenuCommand.prototype.addOriginalCommands, Scene_Menu.prototype.createCommandWindow, Sprite_Battleback.prototype.battleback1Name, Sprite_Battleback.prototype.battleback2Name, Game_Enemy.prototype.makeActions, Game_Action.prototype.makeDamageValue, Window_BattleLog.prototype.updateWaitMode, Spriteset_Battle.prototype.createLowerLayer, Spriteset_Base.prototype.update, Spriteset_Map.prototype.createCharacters, Game_CharacterBase.prototype.setDirection, Game_Event.prototype.update, Sprite_Character.prototype.updateBitmap, Sprite_Character.prototype.characterPatternY, Sprite_Character.prototype.updateOther, Sprite_Character.prototype.updateHalfBodySprites, Sprite_Character.prototype.updateVisibility, Sprite_Battler.prototype.createDamageSprite, Sprite_Actor.prototype.updateBitmap, Sprite_Actor.prototype.update, Sprite_Enemy.prototype.updateBitmap, Sprite_Enemy.prototype.updateCollapse, Sprite_Enemy.prototype.update.

Because nothing is clobbered, Storied Systems co-exists with other plugins that patch the same seams, including large suites.

It also extends 4 methods on core singletons, the same way: original saved and called through: BattleManager.startInput, BattleManager.endAction, BattleManager.setup, BattleManager.startAction. Another plugin patching those keeps working.

It also defines 3 methods that their core class only inherited: Game_Enemy.prototype.clearTpbChargeTime (inherited from Game_Battler), Game_Enemy.prototype.initTpbChargeTime (inherited from Game_Battler), Game_Enemy.prototype.startTpbTurn (inherited from Game_Battler). That touches Game_Enemy only, never the parent. If another plugin redefines the same method on the same class, load Storied Systems after it.

Delve: run maps

  • Every run draws a branching chart in ink and wash through your own troops, common events, shops and rest sites.
  • Four terrains (forest, crypt, coast, spire), reward drafts of three, an act boss sealed at the top.
  • Generated under fairness rules, so no route is a dead end. One plugin command starts a run.

Foresight: enemy intents

  • Every enemy shows the move it has already chosen: the kind of move, its element, the damage it will do to the party member it picked.
  • Attacks that meet a telegraphed attack clash, and the stronger breaks the other.
  • Bluffs, sealed moves and a Scan state through note tags.

Aside: party skits

  • A paper tab offers a short optional scene; the player chooses to watch it, or misses it.
  • Staged with your own face graphics over the map painted down. Party chat and a skit log in the menu.

Papercut: paper cutouts

  • Your own character sheets and battlers re-struck as paper cutouts: a die-cut edge from each silhouette, a card back mid-turn, a lifted shadow.
  • 20 paper stocks. Characters flip to turn, on the map and in battle.

Tested together

  • A Delve battle shows Foresight's plates over Papercut's cutouts; an Aside skit plays on the cut map.
  • One save carries all four parts, and still loads with any one part turned off.
  • The same checks pass with the files in alphabetical, reversed and shuffled order.

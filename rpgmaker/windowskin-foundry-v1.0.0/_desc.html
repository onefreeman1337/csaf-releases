Give every window in your game a worked-material frame. 44 windowskins in RPG Maker MZ's own layout: a chamfered rim lit from the upper left, a plate seated in each corner, a shadow cast onto the window back, and a back textured with the material's own finish. Eleven materials (Iron, Steel, Blued Steel, Pewter, Silver, Brass, Bronze, Copper, Gold, Oak, Cut Card) by four corner ornaments (Stud, Bolt, Rosette, Volute).

Then make them yours. A playtest command reads the tileset of the map you are standing on, finds its three main hues, and re-strikes any skin into the one you pick, writing a new PNG into img/system. Your game's frames end up in your game's colours, with the text colours re-checked to read at 4.5:1 or better.

⚠️ Compatibility — the question you actually have

Tested against RPG Maker MZ with the stock scripts unmodified, verified by running the plugin in the real engine rather than only in tests.

Plugin Manager order:

  1. WindowskinFoundryCore.js — Windowskin Foundry core: reads a palette from tileset pixels and re-strikes a windowskin into it. Load with WindowskinFoundry.js.
  2. WindowskinFoundry.js — Windowskin Foundry: worked-material windowskins (brass, iron, oak and more), chosen per game or in play.

Core methods extended — 3 by saved-original prototype extension, none replaced: Window_Base.prototype.loadWindowskin, Window_Base.prototype.update, Scene_Base.prototype.update.

Because nothing is clobbered, Windowskin Foundry co-exists with other plugins that patch the same seams, including large suites.

It also extends 3 methods on core singletons, the same way — original saved and called through: ColorManager.loadWindowskin, ColorManager.textColor, ColorManager.pendingColor. Another plugin patching those keeps working.

Why a plugin and not just images

RPG Maker MZ reads every text colour from img/system/Window.png once at startup and never from a window's own skin, so a skin under any other name draws the default colours. The plugin points the colours at the skin in force, so each skin's own text and label colours appear, and it redraws open windows once when you switch. Your own Window.png is never touched; blank the parameter to go back to it.

Made for the way the engine stretches a window

MZ copies a skin's 24 px corners as they are and stretches its edges to fit the window. So every ornament sits in a corner and every rim is the same along its whole length: a message box 800 px wide shows no smearing. The material's grain lives in the tiled pattern layer, at full size.

The re-strike

  • Runs only in a playtest, because it writes a file. In a shipped game it does nothing.
  • Offers three hues per tileset (most used, second, third). The most used hue of many outdoor sets is the ground; the second and third are often the water, crystal or lava that make the set.
  • Keeps the frame's light and shade and changes its colour: coloured sources (Brass, Gold, Copper...) come out as enamel, grey sources (Iron, Steel, Silver...) as tinted metal.
  • Anything it would replace is copied to a backup folder first. If a tileset image cannot load, it refuses with the reason and the game keeps running.

How it was tested

Run in the real RPG Maker MZ runtime from the exact zip you download, installed into a blank project: all 44 skins switched in play with every text colour checked against the file's own pixels, the re-strike run on a real map's tileset at all three hues, saves, backups, both plugin orders, a blank parameter and a missing file. The adversarial pass found two real problems that are fixed in this release: a mistyped skin name used to stop the game on "Failed to load" (now refused with a console warning), and windows from other plugins that keep their own skin are now left alone. On the main menu with skins switching in play, a frame costs 28 draw calls with no growth in display objects. The store images use a serif in a showcase scene; the skins do not change your game's font.

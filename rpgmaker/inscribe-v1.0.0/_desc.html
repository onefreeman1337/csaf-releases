Names and answers, written onto an object.

Inscribe replaces RPG Maker MZ's name screen. The stock screen is a grid of letters in a window; Inscribe draws the moment as an object being written on: a guest register signed in ink, a name carved in stone, travel papers stamped by the office, a typed form, a sigil traced into a circle, a headstone at night. The player types on the keyboard, or presses keys drawn in the object's own material with a pad, a mouse or a finger.

The same scene asks questions. Inscribe Answer checks what the player writes against the answers you accept, forgiving case and spacing and, when you allow it, accents, punctuation and a typo or two. Right or wrong shows on the object: gilded, stamped, struck out, cracked. The result goes to a switch, the attempts and the typed text to variables.

⚠️ Compatibility — the question you actually have

Tested against RPG Maker MZ with the stock scripts unmodified, verified by running the plugin in the real engine rather than only in tests.

Plugin Manager order:

  1. InscribeCore.js — Inscribe 1/3 - the rules: rites, the entry buffer, forgiving answer checks and name suggestions from your database. No engine code.
  2. InscribeDraw.js — Inscribe 2/3 - the look: each rite drawn as an object (a register signed in ink, a name carved in stone, ...). No engine code.
  3. Inscribe.js — Inscribe 3/3 - name entry and riddle answers written onto an object: a register, a carved stone, stamped papers, a typed form, a sigil, a grave…

Core methods extended — 3 by saved-original prototype extension, none replaced: Game_System.prototype.initialize, Game_Interpreter.prototype.command303, Game_Interpreter.prototype.updateWaitMode.

Because nothing is clobbered, Inscribe co-exists with other plugins that patch the same seams, including large suites.

Already restyling the stock name screen? Turn the parameter Replace Name Input Processing off and that screen stays; use the command Inscribe Next Name for the moments you want a rite. In a project whose language is Japanese the stock kana screen is kept.

What is in it

  • Six rites, each its own object and its own keys: the register (brass plates), the stone (stone tiles), the papers (rubber stamps), the typed form (typewriter keys), the sigil (wax seals) and the headstone (bone tiles).
  • Every name makes its own sigil. Each letter is a point on an alphabet wheel and the trace runs from letter to letter, so no two names leave the same mark.
  • It fills itself from your project: the register's earlier entries are your other actors, the form's occupation is the actor's class, the papers' place of origin is the map you are on, the portrait is the actor's face.
  • Suggest writes a new name each press, made from the names in your own database blended with a list fitted to the rite. Never a name you already have, never one letter away from one.
  • Riddles and passwords: several accepted answers, typos forgiven up to a third of the answer, attempts, show the answer when they run out, let the player give up.
  • Choose the rite per actor with a notetag (<Inscribe Rite: stone>), per event with a command, or for the whole game with a parameter.
  • Keyboard, pad, mouse and touch. Typed letters never reach the engine's own keys, so "z" is a letter, not OK. Accented letters and digits on a second page.
  • Any screen size: laid out for 816 x 624 and scaled to fit, tested at 1280 x 720, 1104 x 624 and 640 x 480.

Measured, not promised

  • With a fast typist on the sigil (a letter every 8 frames) the scene draws in 2 draw calls per frame with no MZ window drawn; the written line is redrawn only when a letter changes.
  • Tested in the real MZ engine on the stock database: any load order, a missing sibling file, a Japanese locale, battle, sounds set to (None), input spam on every rite, a 300-character question, thirty opens and closes, and a save taken mid-way.

Install

Copy the three files into js/plugins and turn them on in the Plugin Manager. Every Name Input Processing in your game now opens Inscribe. The Readme in the download covers every command, parameter, script call and the save record.

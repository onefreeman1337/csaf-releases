Rally turns walking sprites into side-view battlers for RPG Maker MZ: 3 plugins build all 18 battle motions for your party and your enemies, and 13 combat poses on the map.

Three parts, 6 raw JavaScript plugin files, no image files. Use one part, any two, or all three: each works alone, and all three were tested together in the engine. Licence: any commercial or free RPG Maker project, no royalty; the source may not be redistributed as a plugin pack.

⚠️ Compatibility: the question you actually have

Tested against RPG Maker MZ with the stock scripts unmodified, verified by running the plugin in the real engine rather than only in tests.

Plugin Manager order:

  1. PostureCore.js: Posture core - derives sitting, kneeling, lying, sleeping, collapsed, waving and cheering frames from a walking sheet. Place ABOVE Posture.
  2. KnackCore.js: Knack core - derives 12 looping work animations (with a drawn tool) from a walking sheet. Any order works; PostureCore, KnackCore, Knack reads best.
  3. RallyCore.js: Rally core - builds an 18-motion side-view battler sheet from a walking sheet (facing left for actors, right for foes) and the same poses on the map...
  4. RallyActors.js: Rally Actors - side-view battlers built from each actor's walking sprite: all 18 motions, the equipped weapon drawn in. No SV art needed.
  5. RallyFoes.js: Rally Foes - any character sheet fights as a side-view enemy: the 18 derived motions, built from the sheet's own right-facing row.
  6. RallyField.js: [CSAF] Rally Field: 13 combat poses on the map in all four facings, made from each character's own walking sheet.

This order reads sensibly in the list and nothing depends on it. Every check of the three parts working together was run three times, with all 6 files in this order, in reverse order and in a shuffled order, and passed each time. Install only the parts you want: the three cores plus that part's file. Rally Actors and Rally Foes both extend Scene_Battle.create and Scene_Battle.terminate, and each calls the original it saved, so both parts' additions run in either order. PostureCore.js and KnackCore.js are the same files Posture and Knack ship, byte for byte: keep one copy.

Core methods extended: 24 by saved-original prototype extension, none replaced: Sprite_Actor.prototype.updateBitmap, Sprite_Actor.prototype.setupWeaponAnimation, Scene_Battle.prototype.create, Scene_Battle.prototype.terminate, Game_CharacterBase.prototype.update, Game_Player.prototype.canMove, Game_Follower.prototype.chaseCharacter, Game_Player.prototype.performTransfer, Game_Interpreter.prototype.updateWaitMode, Sprite_Character.prototype.updateBitmap, Sprite_Character.prototype.characterBlockX, Sprite_Character.prototype.characterBlockY, Sprite_Character.prototype.characterPatternX, Sprite_Character.prototype.patternWidth, Sprite_Character.prototype.patternHeight, Sprite_Character.prototype.updateCharacterFrame, Sprite_Balloon.prototype.updatePosition, Sprite_Enemy.prototype.updateBitmap, Sprite_Enemy.prototype.updateFrame, Sprite_Enemy.prototype.update, Sprite_Enemy.prototype.updateStateSprite, Sprite_Enemy.prototype.startBossCollapse, Game_Enemy.prototype.performAction, Game_Enemy.prototype.performDamage.

Because nothing is clobbered, Rally co-exists with other plugins that patch the same seams, including large suites.

It also extends one method on a core singleton, the same way: original saved and called through: BattleManager.processDefeat. Another plugin patching that one keeps working.

It also defines 4 methods that their core class only inherited: Game_Enemy.prototype.performEvasion (inherited from Game_Battler), Game_Enemy.prototype.performMagicEvasion (inherited from Game_Battler), Game_Enemy.prototype.performCounter (inherited from Game_Battler), Game_Enemy.prototype.refresh (inherited from Game_Battler). That touches Game_Enemy only, never the parent. If another plugin redefines the same method on the same class, load Rally after it.

Rally Actors: your party

  • Any actor with a walking sheet and no SV battler image fights in MZ's own side-view battle.
  • A full 9 x 6 battler sheet is built at the start of a battle: all 18 motions, 3 frames each.
  • The equipped weapon is drawn in: 12 weapon forms plus bare hands, picked through MZ's own attack motion table.

Rally Foes: your enemies

  • Tag an enemy with a character sheet and it fights facing the party with the same 18 motions, from the sheet's own right-facing row.
  • It walks in, steps forward on its turn, recoils, kneels when hurt, falls and cheers if the party falls.
  • The bandit the player met in town is the bandit they fight.

Rally Field: on the map

  • One plugin command poses the player, a follower or any event: 13 combat poses in all four facings.
  • Once, hold or loop, with a wait for cutscenes. Saved with the game.

Tested together

  • Both sides of one battle on Rally sheets, fought to a win.
  • A hero's map pose is his battle sheet, pixel for pixel: 78 of 78 cells measured.
  • One save carries all three parts and still loads with any one turned off. The same checks pass in three plugin orders.

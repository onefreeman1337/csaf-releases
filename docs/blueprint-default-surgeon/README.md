# Blueprint Default Surgeon

**Finds every placed actor whose properties have silently drifted from its Blueprint default, and
fixes the drift in either direction — at N actors, per property, across every map, with a named
dry-run preview first.**

Unreal Engine 5.8 · Windows · editor-only plugin · full C++ source included.

---

## The problem

A designer tweaks a property on a placed Blueprint actor. That tweak becomes a **per-instance
override**, and from that moment the actor stops tracking the Blueprint default. Weeks later somebody
changes the default — and every actor that was tweaked quietly keeps the old value.

Unreal can already fix this, one actor at a time:

| operation | where it lives | its limit |
| --- | --- | --- |
| **Reset Instance Changes to Blueprint Default** | actor right-click menu | the menu entry appears only when **exactly one** actor is selected |
| **Apply Instance Changes to Blueprint** | actor right-click menu | also **one** actor |

Both are **all editable properties or nothing**, both act on the **currently loaded level**, and
neither ever tells you **which** properties it is about to overwrite.

This plugin lifts both operations to a selection, a class, or an entire project — and adds the
property-level choice and the preview.

## Quick start

```
UnrealEditor-Cmd.exe <YourProject>.uproject -run=BlueprintDefaultSurgeon
```

That is a **scan**. It writes two files to `<Project>/Saved/BlueprintDefaultSurgeon/` and changes
nothing:

- **`proof_sheet.html`** — a self-contained page: what drifted, grouped by Blueprint, with the
  Blueprint default and the instance value side by side.
- **`plan.json`** — the same information as reviewable data, in a stable order.

Read the sheet. Then, when you agree with it:

```
:: preview - still writes nothing, but re-runs the whole apply and counts what would change
UnrealEditor-Cmd.exe <YourProject>.uproject -run=BlueprintDefaultSurgeon -Apply

:: write it, and save the affected maps
UnrealEditor-Cmd.exe <YourProject>.uproject -run=BlueprintDefaultSurgeon -Apply -Execute
```

**`-Execute` is a second switch on purpose.** The operation overwrites values a level designer may
have set deliberately, across many actors at once, so the destructive path requires naming both the
operation and the intent. One mistyped flag cannot change your project.

## Switches

### Scope

| switch | effect |
| --- | --- |
| `-Paths=/Game/Maps+/Game/Levels` | Content paths to scan. Default: all of `/Game`. |
| `-Blueprints=BP_Lamp+BP_Door` | Only actors generated by these Blueprints. Accepts the asset name or the full object path. |
| `-Properties=Intensity+AttenuationRadius` | Only these properties. Default: every eligible property. |
| `-IncludeTransform` | Also consider location, rotation and scale. **See the warning below.** |

### Direction

| switch | effect |
| --- | --- |
| `-Direction=reset` | *(default)* Instances discard their override and re-take the Blueprint default. |
| `-Direction=push` | The instance's value is promoted to **become** the Blueprint default, for every existing and future instance. |

An unrecognised direction is **refused**, not defaulted — defaulting would silently run an operation
you did not ask for because of a typo.

### Mode and output

| switch | effect |
| --- | --- |
| *(none)* | Scan only. Writes the plan and the proof sheet. |
| `-Apply` | Also run the apply in **preview**. Still writes nothing. |
| `-Apply -Execute` | Write the changes and save the affected packages. |
| `-Out=<dir>` | Where the plan and sheet go. Default `<Project>/Saved/BlueprintDefaultSurgeon`. |
| `-Help` | The full usage text. |

### Exit codes

CI branches on these, so they are fixed:

| code | meaning |
| --- | --- |
| `0` | No drift found within the requested scope. |
| `1` | Drift found, or applied. **This is a result, not an error.** |
| `2` | The run could not be completed. |
| `3` | The arguments were not understood. |

⚠️ `0` and `1` are deliberately not "success and failure". A run that worked perfectly and found 240
drifted properties exits `1`, because that is what a CI job wants to know. A run that could not do
its job at all exits `2` — *"your level regressed"* and *"the tool broke"* are different mornings.

## ⚠️ `-IncludeTransform`: read this before you use it

**A placed actor is *supposed* to differ from its Blueprint default in location, rotation and scale.
That difference is the act of placing it.** A reset that includes transform properties will move your
actors back toward their default placement.

Transform-bearing properties are therefore **excluded by default** and including them is explicit.
Preview before you ever combine `-IncludeTransform` with `-Execute`.

## How drift is decided

For each property on a placed actor:

```
CPF_Edit, and not transient, and not edit-disabled-on-instance
    -> compare the instance against the Blueprint class default
    -> using FProperty::Identical_InContainer, the engine's own comparator
```

**And the same comparison runs on every component**, not just on the actor. That matters more than it
sounds: in practice most per-instance overrides are on components — a light's `Intensity`, a mesh
component's `StaticMesh`, an override material — so an actor-only tool would report almost nothing on
a real project. Each drifted property is reported against the component it belongs to, so
`PointLightComponent › Intensity` is never confused with the actor's own `Intensity`.

Resolving a component's default takes two lookups, because Unreal keeps them in two places: native
C++ components sit on the class default object, while components added in the Blueprint editor live
as templates on the generated class's construction script and are inherited down the Blueprint
hierarchy. Both are searched.

⚠️ **Where a component's default genuinely cannot be resolved** — the engine also supports
Inheritable Component Handler overrides, which this tool does not follow — the component is listed on
the report as *"had no counterpart on the Blueprint default"* and skipped. It is never quietly
reported as unchanged.

Some deliberate choices behind that:

- **The engine's comparator, not a byte comparison.** `Identical_InContainer` respects each property
  type's own equality — structs, arrays, soft references. A `memcmp` reports false drift on padding
  and on any type with internal caching.
- **Transient and duplicate-transient properties are skipped.** They are runtime state, not authored
  drift, and comparing them buries the real answer under noise.
- **Edit-disabled-on-instance properties are skipped.** If the engine will not let you edit it on an
  instance, no instance override can have been authored in the editor.
- **References to an actor's own components are never counted as drift.** An instance's
  `RootComponent` is a *different object* from the default's, so a naive pointer comparison reports
  every actor in your project as drifted. A tool that says "everything drifted" has told you nothing.

## What it refuses to do

- **An actor whose class was not generated by a Blueprint** has no Blueprint default to compare
  against. Reported by name, skipped.
- **An actor whose class default object cannot be resolved** is refused rather than guessed at.
- **World Partition / One File Per Actor maps.** Their actors are not reachable from a commandlet, so
  this tool cannot judge them. It **counts them and says so on the report** — a clean result that
  silently excluded a partitioned map would be a lie by omission.
- **A plan written by a different predicate version.** The plan carries the version of the drift
  predicate that produced it. If a later build reasons differently, the plan you approved and the
  edits that would happen are not provably the same set, so it is refused with a message telling you
  to re-scan. Refusing is cheap; reconciling would be a guess about your level.
- **Reporting a verdict over an empty scan.** If zero actors were examined, the proof sheet prints
  *"No verdict"* and says why. A confident "no drift" over a scan that never looked at anything is
  worse than no report at all.

## Safety

- **Dry run is the default**, everywhere. A default-constructed options struct cannot write.
- **One transaction per batch.** A bulk change is a single Ctrl+Z. A dry run opens no transaction at
  all, because a preview appearing in your undo stack is a lie about what happened.
- **The preview runs the same code path as the real run.** It uses the engine's own
  `ECopyOptions::PreviewOnly`, which counts what it would copy and writes nothing. A preview that ran
  different code would be a preview of nothing.
- ⚠️ **The preview count and the applied count can still differ, and the tool tells you when they
  do.** Measured on the verification project, twice, **in opposite directions**: one run planned 174
  properties and applied 167; another planned 101 and applied 102. Both numbers are printed after a
  real run, and a warning names the gap. **The applied count is the one that describes what happened
  to your project.** No claim is made here about why the engine's two counts differ, or which way
  they will differ, because neither was established — only that they can, and that the tool refuses
  to show you one of them alone.
- **Pushing up dirties the Blueprint** and propagates to archetype instances, so a push cannot
  silently apply to new instances only.
- **The plan is stable.** Two runs over an unchanged project produce byte-identical JSON, so you can
  commit it and a diff means something.

### ⚠️ Verify with a second scan — and know what a reappearance means

The only check that does not depend on this tool being right about itself is **running the scan
again** after an execute. Do that; the tool tells you to.

**Some drift will legitimately come back, and that is not a failure.** A component value that a
Blueprint's *construction script* rebuilds — spline curves, instanced-static-mesh instance data — is
re-derived every time the map is loaded. The reset genuinely happened and was genuinely saved; the
Blueprint then rebuilt the value. **Unreal's own one-actor "Reset Instance Changes to Blueprint
Default" behaves exactly the same way.**

Measured on the verification project: 101 drifted properties across 48 actors; after `-Apply
-Execute`, a re-scan in a fresh editor process reported **12 properties on 6 actors** — every one of
them construction-script-derived component data on spline actors. Everything else stayed reset, and
the same 12 came back on a repeat of the whole cycle.

If you want those actors left alone entirely, name the ones you care about with `-Blueprints=` or
narrow to the properties you mean with `-Properties=`.

## Scanning cost

The scan finds maps through the **asset registry** — no blanket load — then opens **one map package
at a time** and releases it. Loading every map at once to inspect actors is a multi-minute hang on a
real project; this is bounded.

Narrow with `-Paths` and `-Blueprints` when you know where you are looking. The report prints the
scope it used, so coverage is always stated rather than implied.

## Compatibility

**Built and verified against Unreal Engine 5.8 on Windows**, with a zero-warning packaging build.
That is the only engine version the build machine has, so it is the only version claimed. Editor
module only — nothing is compiled into a shipping build.

## Installation

1. Copy the `BlueprintDefaultSurgeon` folder into your project's `Plugins/` directory.
2. Restart the editor. It builds on first load.
3. Confirm it is enabled: **Edit → Plugins → Editor → Blueprint Default Surgeon**.

Full C++ source is included and readable. Nothing is minified or obfuscated.

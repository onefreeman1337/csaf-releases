Your mystery game already knows its suspects, clues and statements. Dossier types them up.

Hand Dossier a case and it composes an open manila case file on a lamp-lit desk: a suspect roster typed onto a printed form with a booking photograph beside every name, an evidence index with redaction bars wherever your data says a fact is unknown, carbon copies and telex strips for the statements, rubber stamps struck in red, a paperclip, a strip of evidence tape, and the investigator's red-pencil marks in the margins.

None of it is an imported image. Every sheet, stamp, clip and line of type is drawn in code by a software rasteriser shipped in the package, and the lettering is filled from the outlines of three real typefaces (Oswald, Courier Prime and Caveat, SIL Open Font License, included).

The layout answers the data

  • Three people get full-width cards with large photographs; ten get a two-column roster.
  • Seven clues get two lines each with their descriptions; twenty get a two-column index.
  • A cold case is typed on yellowed, foxed paper; a classified one on onionskin, redacted hard.
  • A suspect's status strikes the stamp across their photograph: SUSPECT, CLEARED, CHARGED, DECEASED, MISSING, WITNESS, INFORMANT, PERSON OF INTEREST, UNIDENTIFIED.
  • A key clue linked to a suspect gets a red-pencil arrow across the spread to that person's photograph; the most-linked suspect has their name circled.
  • An interview is a carbon copy; a phone call, telegram or radio message is a telex strip; low reliability earns a "doubtful" query in the margin.

Unknown is a word, not a blank

An empty field is simply not typed. A field that says it is unknown (?, unknown, redacted, classified, withheld) is blacked out, weighted by what the fact is: a withheld name is blocked out, an alias gets a marker bar, an age is struck through. A sentence that merely contains the word is data and is typed.

52 hand-authored motifs in 10 families, 4 paper stocks

Stamps (8), fasteners (6), tapes (4), folder tabs (6), photo mountings (4), typed blocks (5), hand marks (8), stains (4), redactions (3), and the bond, aged, onionskin and ledger stocks. Every one is drawn by the shipped code; the editor window's motif sheet draws them all.

Nothing is struck over a name

Every stamp, clip, strip of tape and coffee ring is placed by searching candidate spots for one that misses the record. A name, a title, a face, the booking placard and a redaction bar are refused outright. The red-pencil arrow goes through the same search, and when a crowded card leaves no clear approach it stops at the circled name instead of ruling through the file.

Getting Started

1. Import the package. Everything lands under Assets/CSAF/Dossier, and nothing is placed in a Resources folder.

2. Open the demo scene Assets/CSAF/Dossier/Demo/Scenes/DossierDemo and press Play. Four sample cases (active, cold, closed and classified) are composed; the LEFT and RIGHT arrow keys page between them.

3. In the Unity menu bar open Tools > CSAF > Dossier. Pick a case (or one of the four samples) and press Compose spread. Beside the spread, the window explains every choice the composer made and the word in your data that caused it.

4. To author your own case without code: Assets > Create > CSAF > Dossier Case File, fill in the Inspector, and press Compose this case in Dossier at the top of it.

5. From code: build a CaseFile, load the four shipped typefaces with DossierType.FromAssets, and call DossierSpread.Compose(caseFile, type). The result is a Texture2D for uGUI, UI Toolkit or a material. For anything a player opens, compose off the main thread with the Task.Run recipe in the guide.

Technical Information

Features: generates a case-file spread from the buyer's own suspect, clue and statement data; 52 hand-authored motifs in 10 families and 4 paper stocks, all drawn by an included CPU rasteriser; an included TrueType outline reader and typesetter with three OFL typefaces; layout that adapts to the number of suspects, clues and statements; placement search that refuses to strike any mark across a name, title, face, placard or redaction bar; red-pencil leaders from key clues to the people they name; ScriptableObject case assets with an Inspector compose button; an editor window with a derivation panel and a motif sheet; a thread-safe bake path; deterministic output; a runnable demo scene with four sample cases.

Code Modules: CSAF Dossier Runtime (Runtime, all platforms), CSAF Dossier Editor (Editor only), CSAF Dossier Demo (Runtime, sample content).

Number of Unity Visual Scripts: 0. The package contains no Visual Scripting graph assets and no references to the Visual Scripting packages; verified by walking the shipped tree.

Number of .cs Scripts: 34, measured by walking the shipped Assets tree: 30 Runtime, 3 Editor, 1 Demo.

Supported Development Platforms: Windows (Yes), Mac (Yes). Pure C#, no native libraries and no platform-specific code.

Supported Target Build Platforms: all platforms Unity targets. The runtime assembly is plain C# with no platform-specific code; the editor assembly is constrained to the Editor.

Supported Unity Pipelines: Built-In, URP and HDRP. The spread is rasterised into a Texture2D on the CPU and never touches the render pipeline.

Minimum Unity Version: 2022.3. Built and tested against Unity 6000.5.7f1.

Dependencies on other Plugins and/or System Libraries: none. No packages beyond the Unity engine and editor assemblies, no network calls and no telemetry. The three typefaces are SIL Open Font License 1.1 and ship with their notices.

Documentation Link and Installation Guide: the full Dossier guide. The same guide is also included in the package.

Example Project: the package ships a runnable demo scene, Demo/Scenes/DossierDemo, that composes four sample cases on a worker thread. It draws with OnGUI, so it needs no Canvas and runs the same on any render pipeline.

Versioning: 1.0.0, the first public release. Semantic versioning from here: patch for fixes, minor for new motifs, stocks or layouts, major for any public API change.

Support: bug reports and questions through the issue tracker on the repository that hosts the documentation linked above. Please include your Unity version and, if a spread surprised you, the case data that produced it.

Important or Additional Notes: composition is CPU rasterisation, so its cost is proportional to pixel count: a 1920x1080 spread measured 3.1 to 4.1 seconds in the Unity 6000.5.7f1 Editor on a busy build machine and about 1 second at 960x540. That is a sample, not a ceiling. Compose on change, off the main thread, never per frame. The font reader is TrueType only and does not shape complex scripts. The layout sets up to 10 suspect cards, 24 clues and 4 statements; the rest are listed as continued on file. AI disclosure: code yes, graphics yes (the code that draws the spread was AI-written; there is no image model anywhere in the art path), sounds no, text and dialog no.

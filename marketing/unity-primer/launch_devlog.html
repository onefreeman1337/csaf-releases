Primer is out for Unity. It draws the printed how-to-play page, the kind that came folded inside a game box, from your game's own input bindings and tutorial steps.

Why it exists

Input prompt packs give you a sheet of button icons. What they cannot do is lay out a page that knows which key does what in your game, and redraw it when the player rebinds. Primer takes the binding list you already have, so the diagram, the numbered callouts, the leader lines and the legend all come from the same data and move together.

What is on the page

  • FIG. 1 is your active control scheme drawn whole: keyboard, gamepad, or mouse and touch.
  • Bound controls print at full ink with a numbered callout. Controls your game never mentions are ghosted. Controls you list but leave unbound get their own legend row, so a player learns the action exists.
  • The right page is your numbered steps, each with its screenshot re-screened as a two-ink halftone, plus a hazard key.
  • Four paper stocks change the paper, the ink, the dot pitch and the ink spread.

There are 78 hand-authored marks, and every control has a pressed state that is its own drawing. Gamepad buttons are drawn by position, never as a console maker's glyph.

Works with whatever input setup you use

A control is the generic Input System path string. The composing code does not depend on the Input System package, so the legacy Input Manager, Rewired or your own bindings file all produce the same page.

Honest limits: a full 1920x1200 spread with four screenshots measured 3.7 to 5.1 seconds on one machine, so the package documents composing it off the main thread when a binding changes, never per frame. One spread draws one control scheme.

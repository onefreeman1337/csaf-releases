Rename a UPROPERTY and Unreal does not error. It compiles, the editor opens, and every asset that stored a value for the old name quietly loads the constructor default instead.

Epic states the consequence in its own documentation for this feature: renaming a code member "will cause considerable data loss, because Unreal Engine will no longer recognize existing Assets". The remedy Epic names is a [CoreRedirects] block in DefaultEngine.ini, written by hand.

That mechanism works. The difficulty is that writing the block requires knowing what the names used to be, and by the time you need it they are gone. The compiler has the new ones. Your assets have the old ones. Nothing in the editor holds both.

Epic's own engineers hit this constantly: 133 plugins shipped with Unreal Engine 5.8 carry a hand-maintained [CoreRedirects] section — Niagara, Control Rig, GameplayAbilities, MetaSound, PCG, Enhanced Input, Paper2D and 126 more. Every one of those entries was typed by somebody who still remembered the old name. Nothing in the editor generates one.

Measured on real assets

A Blueprint saved 42.0 against a property called Health; another saved 1234.0 against a class called ACRFOldName. The C++ was refactored and both were read straight back off disk, twice:

Refactor, no redirects: BP_CRFTest → 100.0, the constructor default. The saved 42.0 is gone and the load succeeded. — With the generated block: BP_CRFTest → 42.0

Refactor, no redirects: BP_CRFOld → no generated class at all; its parent no longer exists under that name. — With the generated block: BP_CRFOld → 1234.0

Nothing changed between those readings except whether the block was present.

It refuses far more readily than it guesses

A wrong redirect does not error. It loads the wrong data into every affected asset and the load succeeds, so nobody finds out until the values are committed. Types are matched by path first; leftovers are matched by structure within the same kind, and a winner must clear a confidence floor and beat the runner-up by a margin. Failing either is reported as ambiguous with every rival named and scored, and nothing is emitted for it.

-Verify is a measurement, not a claim

It registers the block it just generated in the running editor through the engine's own API, reads every entry back to confirm it is live before opening a single package, then loads every package the asset registry reports as depending on the affected modules and counts what still fails. Packages already resident are counted separately and never as passes.

It never writes a .uasset

Not under -Apply, not under -Verify, not ever. It writes three text files, all to paths you name: the JSON manifest, the ini fragment and the HTML report. Without -Apply every mode is a preview.

Getting Started

Three steps. The first one has to happen before you rename anything — that is the whole point.

1. Enable the plugin. Copy the CoreRedirectForge folder into your project's Plugins/ directory and open the project. It is an editor-only plugin and compiles with your project; no runtime code is added and nothing ships in your packaged game.

2. Capture the reflection surface BEFORE you refactor, and commit the file.

UnrealEditor-Cmd.exe MyProject.uproject -run=CoreRedirectForge -Snapshot="Saved/CRF/before.json" -Apply -unattended -nosplash

This writes a JSON manifest of every class, struct, enum, property, function and enumerator in your own modules. It is the only record of the names you are about to destroy, so commit it to source control. Without -Apply the run is a preview and writes nothing.

3. Rename, recompile, capture again, and diff.

UnrealEditor-Cmd.exe MyProject.uproject -run=CoreRedirectForge -Snapshot="Saved/CRF/after.json" -Apply -unattended -nosplash

UnrealEditor-Cmd.exe MyProject.uproject -run=CoreRedirectForge -Before="Saved/CRF/before.json" -After="Saved/CRF/after.json" -Out="Saved/CRF/redirects.ini" -Report="Saved/CRF/report.html" -Apply -Verify -unattended -nosplash

Open report.html, read what it emitted and what it refused, then paste the [CoreRedirects] section from redirects.ini into your Config/DefaultEngine.ini and restart the editor. If that file already has a [CoreRedirects] header, paste only the + lines under the existing one — the engine reads the section once.

From the editor console instead: CoreRedirect.Forge Before=... After=... Out=... Apply Verify. Run -Help on either surface for the full switch table.

In CI: gate on the commandlet (-run=CoreRedirectForge), not on the console command. A headless editor does not surface the console path's requested code as the process exit code — it always exits 0. That is engine behaviour rather than a defect here, and the tool logs its code so you can read it from the log if you need the console form.

Technical Information

Type of asset: Code Plugin (Editor)

Features:

Captures a project's live reflection surface to a reviewable JSON manifest — every class, struct, enum, property, function and enumerator, with its parent class, its C++ type and its declaration order

Diffs two manifests across a real refactor and GENERATES the [CoreRedirects] block, using the reflected type names read off the live UClass rather than parsed from a header

Emits ClassRedirects, StructRedirects, EnumRedirects, FunctionRedirects and PropertyRedirects, grouping every renamed enumerator of one enum into a single ValueChanges entry as the engine's grammar requires

Refuses rather than guesses: ambiguous matches are reported with every rival named and scored, and a member that vanished with no plausible successor is reported with no invented target

Every emitted entry carries its confidence AND its margin, because a high score with a small margin is the dangerous case

-Verify registers the generated block in the running editor, reads every entry back to confirm it is live, then re-loads every dependent package and reports residual resolution failures

Designed HTML report; absolute paths are reduced to filenames before they reach the page

Six documented exit codes for CI, and asset discovery through the dependency graph so nothing is loaded in order to decide what to load

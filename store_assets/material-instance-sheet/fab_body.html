Unreal removes the Property Matrix the moment a Material Instance is selected. That is not an oversight and it is not a bug: AssetFileContextMenu.cpp clears bCanUsePropertyMatrix for materials, under a comment about their dependencies with the rendering thread. The consequence is that retuning a family of forty variants means opening forty assets, and there is no first-party path around it.

Material Instance Sheet is that path. It exports every parameter override across a folder or a material family into one CSV — one row per instance, one column per parameter, with a reference row per parent carrying the defaults the instances inherit — and it imports the edited sheet back, writing the overrides into the assets.

Built for the write, not the read

An exporter is an afternoon. The reason this is a product is everything that happens on the way back in:

  • A dry run by default. Nothing is written without -Apply.
  • An undo journal written before the first package is touched. If the editor dies halfway through four hundred assets, the only thing that can put them back is a file that was already on disk when the first one changed. -Revert replays it, and the revert writes its own journal.
  • Every written value read back out of the asset. A void setter has told you nothing. Anything that does not read back is reported as a failure, never counted as a success.
  • Epic's own post-write sequence — PreEditChange / PostEditChange / UpdateStaticPermutation — so the change propagates down the instance chain.
  • A blank cell removes an override rather than writing a zero, which is the operation the editor UI makes most tedious at scale.

It refuses instead of guessing

Every one of these refuses the whole run — including the rows that were fine, because a sheet that is wrong somewhere is not a sheet you want half of:

  • a column header that does not parse
  • a value that is not a number, or a switch that is not true/false
  • a value for a parameter the material does not have
  • a vector with some channels filled and some blank (an instance stores one colour per vector parameter, not four independently overridable floats)
  • a row with the wrong field count, which a deleted comma would otherwise turn into a silent left-shift that clears every override to its right
  • two columns claiming the same parameter

A build gate, not just a tool

Commit the sheet beside your content. A CI step running the import with -FailOnDrift and no -Apply exits 4 the moment a material instance is hand-edited away from the agreed values, and the HTML report names the asset, the parameter and both values. Six documented exit codes, each one a distinct condition a build step can branch on — including the difference between "your sheet is malformed" and "your sheet is not where you said it was".

The report

Every run writes a designed HTML sheet: colour swatches for vector parameters, a before and after for everything else, and on an export a coverage table showing which parameters the family actually varies — so a value every instance inherits reads as a change to make once on the parent, and a parameter no instance agrees with the parent about tells you the parent's default is wrong.

Scope, stated plainly

Scalar, vector, double vector, texture, texture collection, runtime virtual texture, sparse volume texture and static switch overrides are all carried. Font and parameter-collection parameters are exported read-only so the sheet is a complete picture, and the import refuses to move them. Static component mask and terrain layer weight parameters are not modelled — an export says so by name and count rather than leaving you to find out, and an import neither refuses over them nor disturbs them.

Technical

  • Unreal Engine 5.8, Win64. Editor module, full C++ source, no content.
  • Asset discovery through the asset registry; parameter values are not registry tags in 5.8, so the candidate set is loaded and the report prints how many were found against how many were opened.
  • Runs as a commandlet (-run=MaterialInstanceSheet) or from the editor console (MaterialSheet.Run).
  • Eight automation tests, run rather than merely compiled, covering the header grammar, the CSV reader, value canonicalisation, the refusal rules and every documented exit code.
  • Both entry points were exercised against a real 40-instance project, and the sheet the editor console produces is byte-identical to the commandlet's.

No other engine version has been tested, so no other version is claimed.

Relink - Repair SerializeReference Data After a Rename in Unity 6

Relink - Repair SerializeReference Data After a Rename in Unity 6 is a Unity editor tool for Unity, paid.

Its title or description names Unity 6.

Rename a class, move it to another namespace or another assembly, and every [SerializeReference] value of that class goes null in the Inspector. The data is still in your scene, prefab and ScriptableObject files, under the old type name. Relink finds every one of those entries across the project, proposes the class each one belongs to now, and points them at it, so the values come back.

What it does Scans the files, not just what is loaded. Relink reads the text of every scene, prefab and asset under Assets (and embedded or local packages), so assets nobody has opened are covered. Sees the entries Unity's own check misses. A value added through a prefab instance's overrides is stored as an override line.

Measured on 6000.5.7f1: after a rename, Unity's HasManagedReferencesWithMissingTypes returns false for that instance and the only trace is console errors when the scene opens. Relink reads and repairs the override lines too. Proposes the right class from your own data. The class name, and the field names Unity kept under the missing entry.

A class that only moved is matched by name; a renamed class by its stored fields plus name similarity. Refuses to guess.

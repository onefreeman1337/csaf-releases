Unity strips unused assets when it builds. Its own manual documents the single exception: assets in a Resources folder are never removed, because the engine cannot know which one a script will ask for by name at runtime. So everything in Resources ships, in every build, forever.

Ballast reads your load sites, decides which of those assets nothing can ever ask for, moves them out of the build, and hands you a drawn certificate showing exactly how many bytes left.

It never claims an asset is dead. It proves an asset is unreached, and where the question cannot be answered it refuses to act and names the line of your code that stopped it.

Three answers, and the third is the one that earns the price

  • IN USE - a literal load site resolves to this asset. Kept, and the file and line that reached it are cited beside the verdict.
  • UNREACHED - no literal resolves to it and no dynamic site could reach it. Offered for migration.
  • WITHHELD - a dynamic load site could reach it. Never touched, and the call site that made it undecidable is named.

Loading from Resources takes a string. A plain literal path is decidable. A path built by concatenating a variable taints that folder. A LoadAll call claims the whole folder. A load site built entirely at runtime taints the entire tree, and in that case Ballast migrates nothing and tells you why. That is the correct answer, not a failure: a tool that guessed would eventually move an asset your game loads, and you would find out when a player hit that path.

Safety is the design, not a setting

Assets are migrated, never deleted. They move into a quarantine folder keeping the shape they came from, and the meta file travels with each one, so GUIDs survive and every existing reference in every scene and prefab still resolves. Revert is one click and replays the manifest, so it is a true inverse rather than a second guess at the path. Nothing runs on import, nothing runs on build, and the whole pass is read-only until you confirm a count.

One detail worth knowing because you will see it: inside the quarantine the Resources segment is renamed. Unity decides what ships by looking for a folder named exactly Resources at any depth, so preserving the original shape verbatim would leave the quarantined bytes in the build and achieve nothing. It is a rename rather than a tilde-suffixed folder on purpose, because a tilde folder is ignored by Unity entirely, which would drop the assets out of the AssetDatabase and break the very references this package exists to protect.

The report is a document, not a list

The certificate carries a tonnage bar per top-level Resources folder sized by real bytes, the reached fraction struck solid and the unreached fraction outlined, a cross-hatched band for the withheld tonnage, the displacement figure set large, and a dateline. The three verdicts are drawn in three different visual languages rather than three colours, so the plate still reads on a greyscale screenshot. Seven paper stocks; export to PNG.

Getting Started

  1. Import the package. Everything lands under Assets/CSAF/Ballast/.
  2. In the Unity menu bar, open Window > CSAF > Ballast. The Ballast window opens as a dockable editor window; there is no scene setup, no prefab to drag in and no play mode required.
  3. Press Survey. Ballast reads every Resources folder in the project and every load site in your C#, then lists each asset with its verdict: IN USE, UNREACHED or WITHHELD.
  4. Press Compose certificate to draw the lading plate, and Export PNG to save it.
  5. Optional, and only when you are satisfied with the list: press Migrate to move the UNREACHED assets into the quarantine folder. The confirmation names the count and the byte total first, and Revert puts everything back.

Nothing runs on import, nothing runs on build, and nothing is deleted at any point.

Technical Information

Features: static reachability analysis over every Resources load, LoadAll and LoadAsync call site in the project, found by a real C# lexer rather than a regex, so a call commented out, inside a preprocessor block, or written inside a string literal is not mistaken for a live one; verbatim, interpolated and verbatim-interpolated strings handled in either order; three-verdict classification with taint propagation from dynamic sites; per-asset citation of the file and line that reached it; quarantine migration with the meta file preserved and a manifest-replayed revert; segment-wise exact folder matching, matching Unity's own rule; a drawn lading certificate composed on demand and cached, with seven stocks and PNG export; a demo scene; zero shipped image, audio or font assets.

Code Modules: CSAF Ballast Editor (Editor only), CSAF Ballast Demo (Runtime, all platforms, sample content).

Number of Unity Visual Scripts: 0. The package contains no Visual Scripting graph assets and no references to the Visual Scripting packages; verified by walking the shipped tree.

Number of .cs Scripts: 17, measured by walking the shipped Assets tree - 16 Editor, 1 Demo.

Supported Development Platforms: Windows (Yes), Mac (Yes). Pure C#, no native libraries and no platform-specific code.

Supported Target Build Platforms: all platforms Unity targets. Ballast is an editor tool and ships nothing into a build; its own editor assembly is platform-constrained to the Editor.

Supported Unity Pipelines: Built-In, URP and HDRP. The certificate is rasterised into a Texture2D on the CPU and never touches the render pipeline, so it is pipeline-agnostic by construction.

Minimum Unity Version: 2022.3.

Dependencies on other Plugins and/or System Libraries: none. No packages beyond the Unity engine and editor assemblies, no network calls and no telemetry.

Documentation Link and Installation Guide: Ballast user guide - the same guide is also included in the package.

Example Project: the package ships a runnable demo scene containing a specimen behaviour, so a reviewer can open it and press Play. The survey itself runs from the editor window rather than from play mode, because it reads the project on disk.

Versioning: 1.0.0, the first public release. Semantic versioning from here: patch for fixes that do not change a verdict, minor for new certificate stocks or scanner coverage, major for any public API change. A verdict can only ever become more conservative in an update, never less.

Support: bug reports, questions and scanner coverage requests through the issue tracker on the csaf-releases repository linked under Documentation above. Please include your Unity version and, if a call site was classified in a way that surprised you, the shape of that call site.

Important or Additional Notes: the certificate is drawn by a CPU rasteriser, so its cost is proportional to pixel count. Measured across three runs in a blank 6000.5.7f1 project, the default 1100x1500 plate composes in 1.46 to 1.80 seconds, and the high figure is an observation rather than a ceiling. Compose on demand and cache; never on a repaint. Textures returned by the composer belong to the caller and should be destroyed when finished with. AI disclosure: code yes, graphics yes, sounds no (the package contains no audio file of any kind), text and dialog no. There is no image model anywhere in the art path; graphics is disclosed as yes because the code that draws the certificate was AI-written.

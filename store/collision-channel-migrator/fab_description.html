Insert, delete or reorder a custom collision channel and Unreal quietly splits your project in half. Half of it is fine, half of it now means something else, and the half everybody checks is the half that is fine.

Delete a channel in Project Settings > Collision and the engine shows a modal reading, word for word: "If you delete this channel, all the objects that use this channel will be set to default. Would you like to continue?" Press Yes and it calls a nine-line function that removes one entry from a config array and refreshes the settings window. No asset is opened, scanned or written. Every object keeps the slot it stored, and that slot now resolves to a different channel.

Why the forums never agree about this

Stored by name, and safe. A body's collision responses are a list of { FName Channel; ECollisionResponse Response }, so each entry carries its channel's display name and is re-resolved on load. Collision profiles are name-keyed too.

Stored by slot, and silently wrong. A body's object type — the channel it is — is FBodyInstance::ObjectType, a TEnumAsByte<ECollisionChannel> holding ECC_GameTraceChannelN: a position in a list. Every Blueprint trace and object-query pin stores TraceTypeQuery3 / ObjectTypeQuery2 the same way. The name you chose lives only in DefaultEngine.ini and is never written into the asset.

So a report that reordering broke a project and a reply that channel order is purely visual are both true, about different fields. The field a developer opens and inspects is the field that was never in danger.

What Epic covers, and where it stops

Epic ships redirects for channel renames — CollisionChannelRedirects maps an old name to a new one. They work, and this plugin does not duplicate them. They are name-to-name. There is no index-level redirect anywhere in the engine, so a rename is handled and an insert, a delete or a reorder is not.

The workflow

  • -Snapshot before you touch a channel. A small JSON file recording which name sat in which slot. Commit it — nothing can reconstruct what a stored 3 meant without it.
  • Change your channels. Restart the editor as Unreal requires.
  • -Plan writes a designed HTML report and changes nothing.
  • -Apply rewrites and saves.

-Audit needs no snapshot and finds every reference to a slot holding no channel at all — the shape behind the engine's own "Custom Channel Name has not been found" warning, and the usual residue of a deleted channel or of marketplace content built against a different table.

It refuses far more than it rewrites

A wrong collision remap does not crash. It ships a build where a bullet passes through a wall.

  • A body driven by a named profile is left alone. Its stored object type is dead data the profile overwrites on load, and setting an object type would detach the body from its profile — so rewriting these would break working assets to change nothing observable. The report says how many and why.
  • A channel that was deleted rather than moved is reported, never guessed at. There is no correct destination.
  • A channel that changed kind — object to trace, or the reverse — has its Blueprint pins refused. The two query enums are different spaces.
  • A pin default that is neither an enumerator of its own enum nor a number is refused rather than rewritten.

Every rewritten value is read back and compared against what was intended before the run is called a success. The undo journal is written before the first package is saved, so a run killed halfway through saving is still fully revertible, and -Revert replays it exactly.

What it scans

UStaticMesh body setups · UPhysicsAsset skeletal bodies · Blueprint component templates in the construction script · Blueprint graph pin defaults typed as ETraceTypeQuery or EObjectTypeQuery, including pins on MakeArray nodes feeding an "object types" array · primitive components on placed actors in maps.

Stated rather than discovered: on a World Partition map only actors in the persistent level are reached, because a commandlet does not load streamed cells. Most collision configuration lives on the source assets and Blueprints above, which are scanned in full.

The scan is asset-registry first and loads only what it has already decided is a candidate — it does not load your whole project to read one property.

Built for CI as well as for a person

Runs as a commandlet with six documented exit codes, each a distinct thing a build step can act on, or from the editor console. Full C++ source included. Editor-only: it adds no runtime code and nothing ships in your packaged game.

Unreal Engine 5.8, Windows 64-bit. No other engine version has been tested, so no other version is claimed.

Getting Started

  • Copy the CollisionChannelMigrator folder into your project's Plugins/ directory and restart

    • the editor. It appears under Edit > Plugins > Editor > Collision Channel Migrator.

  • Before you touch a collision channel, take a snapshot:
UnrealEditor-Cmd.exe "C:\Path\To\YourProject.uproject" -run=CollisionChannelMigrator -Snapshot

That writes Saved/CollisionChannelMigrator/channels.snapshot.json. Commit it.

  • Change your channels in Edit > Project Settings > Engine > Collision, and restart the editor

    • as Unreal requires.

  • See what moved, changing nothing:
UnrealEditor-Cmd.exe "C:\Path\To\YourProject.uproject" -run=CollisionChannelMigrator -Plan

Open the HTML report it names in its final log line —

Saved/CollisionChannelMigrator/collision_channel_migrator.html.

  • When the report reads correctly, run it for real:
UnrealEditor-Cmd.exe "C:\Path\To\YourProject.uproject" -run=CollisionChannelMigrator -Apply
  • To undo, replay the journal the apply wrote:
UnrealEditor-Cmd.exe "C:\Path\To\YourProject.uproject" -run=CollisionChannelMigrator -Revert=Saved/CollisionChannelMigrator/migration.journal.json

No snapshot? -Audit needs none and finds every reference to a slot that holds no channel:

UnrealEditor-Cmd.exe "C:\Path\To\YourProject.uproject" -run=CollisionChannelMigrator -Audit

You can also run any mode from the editor's console: CollisionChannelMigrator.Run -Plan.

Run -Help for the full switch table.

Technical Information

  • Type of asset: Code Plugin (Editor)
  • Features:

    • - Snapshots the collision channel table before a change, so a migration can be done by MEANING rather than by guesswork

    - Rewrites slot-encoded FBodyInstance::ObjectType across static mesh body setups, physics asset skeletal bodies, Blueprint component templates and placed actors in maps

    - Rewrites Blueprint trace and object-query pin defaults (ETraceTypeQuery / EObjectTypeQuery), including pins on MakeArray nodes feeding an object-types array

    - Designed HTML report showing the channel table before and after, with a slot move drawn as a curve, a query-index-only move as a separate marker, and a deleted channel as a tombstone

    - Refuses rather than guesses: profile-driven bodies, deleted channels, channels that changed kind, and unreadable pin defaults are each reported with a reason

    - Undo journal written before the first package is saved; -Revert replays it exactly

    - -Audit mode needs no snapshot and finds references to slots that hold no channel at all

    - Six documented exit codes for CI, and an asset-registry-first scan that loads only candidates

  • Code Modules:

    • - CollisionChannelMigrator (Editor)

  • Number of Blueprints: 0
  • Number of C++ Classes: 1 (UCollisionChannelMigratorCommandlet), plus 7 supporting namespaces in the same module
  • Network Replicated: No (editor-only; contributes no runtime code)
  • Supported Development Platforms: Windows
  • Supported Target Build Platforms: Windows
  • Example Project: No

  • Important/Additional Notes: Editor-only — the module's PlatformAllowList is ["Win64"], matching the Supported Target Build Platforms line above, and nothing ships in your packaged game. -Apply is one-shot per channel change by design: the remap is a function of the value found, so two channels that swapped slots produce a map that is its own inverse — correct once, self-undoing twice.

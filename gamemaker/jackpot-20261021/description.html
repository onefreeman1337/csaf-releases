Slot machines for your GameMaker game, generated and drawn by the package, playable out of the box, and honest about their maths: every machine's return to player is computed exactly from its reel strips, and its pay table can be tuned to the figure you choose. Pure GML, play money only.

Use it for a game corner in an RPG town, a casino level, a festival minigame, a reward machine, or a whole slots game. One call builds a machine from a word; another makes it playable.

// Create: a machine from a word (the same word always builds the same machine)
my_machine = jkp_machine_create({ seed: "Lucky Sevens", theme: "fruit", reels: 5, cabinet: "upright", rtp: 0.94 });
my_slot = jkp_slot_create(my_machine, { credits: 500, lineBet: 1 });
// Step: run it and spin on SPACE
jkp_slot_step(my_slot);
if (keyboard_check_pressed(vk_space)) jkp_slot_press(my_slot, "spin");
// Draw GUI: draw it anywhere, at any scale
jkp_slot_draw(my_slot, 40, 20, 0.9);

What your players see

  • 80 symbols drawn by the package, no image files: eight themes of eight pay symbols, each with its own WILD plaque and SCATTER medallion. Fruit, Gems, Royals (letters on card tiles, ring, chalice, crown), Runes (eight Elder Futhark runes, each in its own stone), Sea, Desert Relics, Candy and Space.
  • Three cabinets in four liveries: an upright with a marquee of chasing bulbs and a pull lever, a slant-top and a bar-top, in lacquer, chrome, wood grain or black and gold. Every machine gets a generated name on its marquee.
  • A machine that feels like one: reels with motion smear that stop one after another and settle with a bounce, paylines that light up one by one, winning symbols that pulse, LED meters that roll up, a coin fountain into the tray, and a BIG WIN banner.
  • The pay table page, drawn from the machine's own symbols, with every pay, the wild and scatter rules, the paylines and the exact return to player.

What you get as the developer

  • Exact payback, not a guess. jkp_rtp computes a machine's return to player exactly from each reel's symbol counts. The tests prove it: playing every one of the 13,824 stop combinations of a 3-reel machine returns the same figure.
  • Tuning. jkp_tune(machine, 0.92) re-tunes the pay table to 92% (or anything from 50% to 120%), keeping whole-number pays and a sensible table. 5-reel machines land within 0.00001 of the target.
  • Statistics. jkp_exhaust3 gives the exact hit rate and swing of a 3-reel machine; jkp_simulate estimates them for any machine from seeded spins.
  • Events for your sounds and your purse: spin, reel stop, win, big win, no win, refused. Credits are plain numbers you can share between machines.
  • Everything is data you can read and edit: strips, paylines, pays, scatter pays. Three cabinets' layouts are exposed for your own art and input.
  • THE GAME CORNER demo room: eight machines, every theme, every cabinet, both reel counts, one shared purse, the pay table and exact figures beside each machine, and a key that re-tunes the machine live.

Tested

GML cannot be unit-tested outside the engine, so every test runs in a real exe built by GameMaker's own compiler (runtime 2024.14.4.268, VM, Windows). The suite holds the GML core to a reference implementation bit for bit (24 generated machines, 240 scripted spins, the tuner at ten targets), checks the exact figure against full enumeration inside the engine, checks every symbol for ink, fit and distinctness, plays all three cabinets to a win with the reels showing exactly the decided outcome, and drives the demo room. The shipped package is also installed into a blank project and the Readme's own code run, and every documented function is attacked with hostile arguments. HTML5, mobile and YYC exports were not built.

Play money only. Nothing in the package takes, holds or pays real money. If you ship slot machines to a mobile or console store, that store's rules on simulated gambling apply to your game.
